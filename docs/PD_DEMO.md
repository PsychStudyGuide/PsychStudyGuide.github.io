# Professional development demo runbook

This is a short, reliable walkthrough of the General Psychology pilot. It demonstrates the product without suggesting that the whole course has already been loaded.

The pilot minimizes the collection and retention of student data, but the application alone cannot confer FERPA compliance. College privacy, accessibility, procurement, and IT reviewers should approve the production workflow before the tool is assigned to students.

## Before the session

1. Publish the current repository update to GitHub Pages.
2. On the presentation computer, open the student site and enter the private course code.
3. Read and acknowledge the funding notice.
4. Choose the correct device setting. Use **Shared or library computer** on a college-owned presentation station.
5. Enter the presenter’s OpenRouter key and choose an approved model.
6. Send one test question, then select **New topic** so the audience sees a clean start.
7. Keep the OpenRouter dashboard available in a separate tab to show that usage belongs to the key holder.

Do this setup before screen sharing. Never display the course code or API key to the room.

## Five-minute walkthrough

### 1. Establish the boundary

Show the **Chapter 1 Review** scope and say:

> This pilot currently contains two General Psychology lectures. The assistant can work only from the material selected on the left.

### 2. Ask a comparison question

Use this prompt:

> How are clinical and counseling psychology different?

Point out the **Directly supported** label and the **Helping professions** source chip. Explain that the model receives only the relevant excerpts. If the app cannot connect an answer to valid retrieved evidence, it withholds the answer as unsupported.

### 3. Demonstrate retrieval practice

Open **Quiz me**, choose **Balanced practice**, and answer the first question aloud. The tool should give brief feedback before it asks the next question. It should never dump all five questions at once.

### 4. Demonstrate a boundary

Start a new topic and ask:

> What does this material say about attachment styles?

Attachment styles do not appear in this two-lecture pilot. The useful behavior is a clear **Not found in this material** response rather than a plausible answer borrowed from general model knowledge.

### 5. Close with the student workflow

Show **Explain it back** and say:

> Students can ask for an explanation, practice retrieval, or explain a concept in their own words. There are no student accounts, grades, or conversation histories sent to a college database in this pilot.

## Points to emphasize

- The public GitHub repository contains an encrypted course bundle, not readable lecture transcripts.
- Students provide their own OpenRouter key. The interface permits only the instructor-approved low-cost lineup and checks the live model catalog.
- Requests require a provider that denies data collection and supports zero data retention.
- The site asks students not to enter names, IDs, grades, diagnoses, or other identifying information.
- This is an optional study aid. College educational resource funds may not be used for OpenRouter credits or related costs.
- The pilot is intentionally narrow. More course material can be added after the workflow and institutional language receive approval.

## If the live model is unavailable

Open **Settings**, choose another approved model, and resend the waiting question. The app preserves the question and explains when a model has been removed or has no compatible provider. If the network itself is unavailable, show the course scope and modes, explain the privacy architecture, and schedule a live follow-up rather than entering credentials into an unfamiliar device or network.

## After the session

On a shared device, select **I’m done / clear my data** or close the tab and verify that the API key is gone. On a personal device, the key remains only in that browser until it is cleared in Settings.
